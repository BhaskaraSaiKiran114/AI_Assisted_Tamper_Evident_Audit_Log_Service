# Account-access report contract - M7

This scope refines Scenario C's assumptions before report implementation. It is an engineering prototype for inspecting reported access attempts, not a regulatory certification or evidence of activity never ingested.

GET /audit/compliance/access-report requires AUDIT_COMPLIANCE. The mandatory from/to occurrence-time range is inclusive/exclusive [from,to), ISO UTC-normalized supported microsecond instants; from < to and window <=31 days. Optional accountId maps to resourceId, actorId to the recorded producer-supplied actor, action to READ/UPDATE/EXPORT and outcome to SUCCESS/DENIED/FAILURE. Filters combine with exact AND semantics; they are not SQL patterns. limit defaults 50, range 1-200; cursor is bounded/signed. Unknown/repeated/blank parameters fail 400. Archived entries are hidden unless includeArchived=true and the caller also has AUDIT_LIFECYCLE.

Only resourceType=CLIENT_ACCOUNT and eventType READ, UPDATE or EXPORT are reportable. A supported **plaintext top-level payload.outcome string** supplies outcome. Missing, null, nonstring, unsupported, or protected-envelope outcomes are excluded and counted in excludedOutcomeCount for the candidates examined in this request. No default success, inference from action, or key unwrap/decryption is performed. Protecting /outcome at ingestion intentionally makes it unavailable to this report; changing configuration later never decrypts historical protected outcomes. This vocabulary leaves ordinary ingestion backward compatible. Other resource/event types are outside the report's declared source scope.

Response entries contain only eventId, sequence, actorId, accountId, action, outcome, occurredAt and archived. Never include payload, key material, other payload fields or an optional includePayload bypass. Account/actor identifiers remain disclosed metadata and are not erased by field-key deletion. Missing unrelated field keys or legitimate redaction does not prevent metadata reporting. Approval for code/tests does not authorize real-client data disclosure.

Report version access-report-v1 binds this vocabulary. Each page uses the existing database-specific read snapshot and validates each examined candidate's canonical bytes/searchable columns plus archive evidence when returned. It does not perform a full-chain/lifecycle verification or prove query completeness; use the separate verifier operation for whole-store integrity. Signed cursor context is domain separated from ordinary queries and binds all report filters/range/limit/archive mode/version and the fixed upper head. Changed/forged/cross-endpoint cursors fail 400; unavailable upper anchor fails 409. Later appends stay excluded. Lifecycle state may change between pages. Current snapshot is not held historically between HTTP requests.

Resource defaults: audit.report.max-window=P31D (positive whole seconds, <=366 days), max-scanned=1000 (1-10000), max-concurrent=2 (1-4), exposed as AUDIT_REPORT_MAX_WINDOW, AUDIT_REPORT_MAX_SCANNED and AUDIT_REPORT_MAX_CONCURRENT. Stream candidates in sequence with a hard scan bound and look ahead for another matching row. More than the scan budget needed to determine a page returns 413 with no partial result; narrow the range/account/action/outcome where useful. The query prefilters account resource type, recognized actions, requested time/actor/account/action and archive mode. Invalid/unsupported outcomes and outcome-filter misses count against the scan budget. Excess simultaneous reports return 429; release capacity on all paths. A 30-second database transaction timeout is not a hard wall-clock SLA.

The response includes reportVersion, entries, limit, nextCursor, snapshotHead, scannedCount and excludedOutcomeCount. Counts describe only this request's scan, including lookahead, not totals for the period and not counts to sum across pages. Cursor resumes after the last returned matching sequence; later candidates can be examined again. Empty/exhausted pages have null nextCursor. No sorting choice, offset pagination, tenant isolation, saved report, signed report delivery, CSV/PDF, legal interpretation, legal hold or aggregation is added. M6 protected export remains a separate capability; this JSON response is not a signed export.

Production questions remain: applicable jurisdictions/retention, source completeness/actor accuracy, the meaning of access/denied/service activity, identifier sensitivity, authorized reviewer scope, tenant controls and independent report delivery requirements. Upstream producers must use the documented vocabulary and report every relevant attempt; the service cannot establish unreported facts. M8 local readiness/measurement is delivered; human acceptance and production scope remain separate.
