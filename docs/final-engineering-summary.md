# Final prototype engineering summary

Updated 2026-10-28. All eight implementation/validation deliverables are complete; candidate acceptance, personal attestation and submission remain pending. Milestone progress is 8/8 (100%), not a reviewer score, legal certification or production-readiness guarantee.

The service implements strict append-only ingestion, encrypted sensitive payload fields, exact versioned SHA-256 chain commitments, combined filtered cursor queries, identity lookup and snapshot full-chain/lifecycle verification. Logical archival preserves immutable evidence; acknowledged selective field-key erasure appends administrative proof and supports idempotent replay/conflict detection. Bounded signed protected exports include selected original bytes and minimal bridging headers; a dependency-free Java 21 JAR verifies them with an independently trusted public key. The explicitly scoped account-access report projects eight metadata fields and counts unsupported/protected outcomes without decryption. Contracts and assumptions are in [requirements](requirements.md), [architecture](architecture.md), [encoding](encoding-v1.md), [reads](query-verification.md), [lifecycle](lifecycle.md), [export](exports.md) and [report](access-report.md).

One Java 21/Maven application with explicit JDBC transactions keeps global-chain reasoning reviewable. PostgreSQL is authoritative; H2 is a disposable demonstration. A single head lock serializes writes and lifecycle commands. PostgreSQL REPEATABLE_READ / H2 SERIALIZABLE read snapshots avoid false concurrent breaks. Domain-separated signed cursors bind filters/range/limit/archive mode and upper-head identity. No event update/delete endpoint exists. Runtime roles lack history mutation/DDL/direct key deletion; the scoped PostgreSQL erasure capability requires matching administrative evidence. Startup migration credentials remain separate from the runtime pool but still in process.

JWT authentication pins RS256 RSA, issuer/audience/subject/time claims and independent WRITE/READ/VERIFY/DOCS/LIFECYCLE/EXPORT/COMPLIANCE permissions. Archive opt-in adds LIFECYCLE. OpenAPI/UI/assets are protected. In-process scan/report/export limits and safe errors fail closed. M8 hardened offline input file reads against growth after size inspection. No new event schema, migration or cryptographic-format rewrite was needed.

Spring Boot remains the requested **4.1.0**. The actual advisory audit found affected component versions, so compatible explicit overrides now use Framework 7.0.10, Security 7.1.2, Tomcat 11.0.27, PostgreSQL JDBC 42.7.14, legacy Jackson 2 BOM 2.21.8, Log4j2 2.25.5 and Swagger UI 5.34.0. Springdoc stays 3.1.0; filtered YAML aligns its WebJar path. The regression caught and corrected a protected-UI 404 without weakening assertions. Dependency-Check was upgraded from 12.1.8 to 13.0.0 after two CVE reference URLs exceeded the old database schema limit. See [security review](security-review.md).

Final patched -Ppostgres-it,readiness clean verify passed **210 checks**: 132 Surefire unit/H2/security, 74 reference PostgreSQL, one portable CLI artifact case and three opt-in real HTTP/readiness cases. Zero failures/errors/skips and zero Checkstyle violations. The exercise demonstrates A/B/C against the actual runtime pool, administrator-only synthetic tampering, lifecycle/export with actual standalone verification, and fresh executable-JAR H2 startup/shutdown. Disposable test clusters and child applications stopped normally. The final readiness gate rebuilt both artifacts under the final POM; their runtime/class bytes match the earlier patched build. Commands, failures/repairs, timestamps and artifact hashes are in [M8 evidence](validation/milestone-8.md).

The final advisory gate passed with engine 13.0.0, 59 dependency records, zero reported vulnerable dependency records and no CVE import errors logged. No project suppression or error bypass was added. Coverage is NVD/CPE and RetireJS using the documented mirror snapshot; OSS Index was automatically disabled without credentials. Data freshness and scope are explicit in the ledger/security JSON. This result does not cover all future advisories, test-only dependencies, JDK/server binaries or configuration-specific exploitability.

A measured 1000-event real HTTP baseline on Windows/i7-1260P/16 logical processors/PostgreSQL 16.3 reached **186.665 appends/second** at concurrency four, p95 **26.570 ms**. Full verification of 1000 records p50 was 240.300 ms; protected export p50 413.095 ms. A further 100-record archival batch/page experiment measured archived page 50 p50 1128.423 ms and post-lifecycle verification of 1102 records p50 254.132 ms. These are one warm local run, not a promised SLO or patch-performance comparison. Small payloads, shared client/server host, no TLS/WAN or long soak and no large lifecycle fanout constrain conclusions. See [measurements](performance.md).

Residual boundaries: coherent privileged history rewrites need independent external evidence; operated checkpoints are absent. Signed hidden-content headers/lifecycle status do not prove complete filter selection, upstream truth or physical erasure. Protected-key deletion is limited to the active store; WAL/backups/replicas/MVCC/caches/in-flight reads/prior disclosures and retained key copies constrain privacy. Metadata/unprotected fields remain exposed. Report vocabulary is a prototype interpretation of producer-supplied CLIENT_ACCOUNT attempts, not jurisdiction-specific compliance. No production KMS/HSM, revocation/rotation, tenant isolation, legal hold or distributed quota is provided.

PostgreSQL 17.6/Compose, external CI, intended production patch level, real backup/key operations, independent human review and real live-change defense remain unverified.
